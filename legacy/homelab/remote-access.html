Homelab · Remote access

Reaching home services with no ports open at home

Outside traffic reaches my home server through a relay on a cloud server and a tunnel, so the home network has no open ports. Tailscale covers private access from my own devices.

The relay path

A small Oracle cloud server acts as the front door. Nginx Proxy Manager, a reverse proxy with a web interface, receives the visitor's request there and hands it to a tunnel server on the same machine. On my Unraid server, a tunnel client (frpc) is linked to that tunnel server, and it passes the request on to the service.

  1. VisitorA request arrives from outside the house
  2. ProxyNginx Proxy Manager on the Oracle cloud server
  3. Tunnel serverAlso on the cloud server
  4. Tunnel clientfrpc on the home Unraid server
  5. ServiceThe app the visitor asked for

No ports are open at home. The only open ports are on the Oracle cloud server. The proxy runs there, not on the home server.

Tailscale for my own devices

Tailscale is a private mesh VPN. It covers private access from my own devices. Frigate and Jellyfin each have their own Tailscale identity, so the camera recorder and the media server can be reached on their own. A small speed test container runs with Tailscale so I can test the remote path.

I also evaluated Twingate and retired it in favor of Tailscale.

Kasm Workspaces: a remote browser, since retired

Kasm Workspaces streams a full desktop browser to any device through an ordinary browser tab. I ran it on its own Ubuntu virtual machine in the cloud, reached through my own domain. From a locked-down Chromebook I could open one tab and be working in a full browser running somewhere else.

What made it good was the isolation. The virtual machine sat apart from my home network by default, so I could let a friend use a workspace without giving them any path into my house. For my own sessions I could allow only my virtual browser to reach the services on my home network, and nothing else on that machine.

It was stable enough to watch video through, although playback was choppy because of the Chromebook's hardware and the limits of the virtual machine. I shut it down after high school because I no longer needed it and it used more memory than the server could spare.
